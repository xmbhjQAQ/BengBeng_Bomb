# 本地挑战记录、昵称记忆与意外退出恢复

## Goal

让用户在同一浏览器中可靠地找回自己创建的挑战与私密结果入口、自动复用常用昵称，并为挑战中途异常退出提供清晰且可控的恢复路径，同时不扩大人脸数据采集范围、不制造重复挑战记录，也不引入持续轮询等额外后端负担。

## Background

- 创建挑战成功后，`ComposerView` 目前只把挑战链接、私密管理链接和有效期保存在 React 状态中；刷新、关闭页面或稍后再访问都会丢失这份入口。
- 私密管理链接包含管理凭证，服务端不会也不应通过普通公开入口再次下发。因此“我的挑战”只能是当前浏览器上的便利记录，不是账号同步或云端备份。
- 创建者昵称和群组参与者昵称目前分别是一次性输入，没有复用机制。
- 单人挑战开始后，服务端状态从 `opened` 变为 `started`，尝试凭证只保存在 `sessionStorage`。普通刷新通常仍可继续，但关闭标签页、浏览器崩溃或系统回收进程后，凭证可能丢失，挑战会停在 `started`。
- 校准数据、人脸检测结果、视频进度和挑战过程分数目前只存在内存中。精确恢复到退出前一秒需要持久化更多敏感且容易失配的状态，不符合现有“人脸数据尽量仅在本地短暂存在”的边界。

## Product Direction

### 1. “我的挑战”本地记录

- 使用浏览器持久化存储保存用户在本机创建成功的挑战，而不是依赖 HTTP 缓存。首选带版本号、容量上限和异常降级的 `localStorage` 小型注册表。
- 每条记录只保存恢复入口和列表展示所需的稳定字段，例如：挑战类型、视频标题/封面标识、创建时间、挑战入口、私密管理入口、群组公开结果入口及服务端已返回的有效期。
- 不保存摄像头画面、人脸特征、校准数据、过程曲线、临时播放地址、解析接口密钥等数据。
- 首页增加“我的挑战”入口；用户可打开挑战、查看私密结果、复制入口、删除单条记录或清空本机记录。
- 默认不轮询后端。列表先使用本地元数据展示，只有用户主动打开/刷新某条状态时才请求服务端。
- 本地记录必须有容量上限并惰性清理无效项；不能仅按单人挑战的创建有效期过早删除，因为挑战完成后的私密结果可能仍在保留期内。
- 本地存储不可用、被浏览器清理或用户更换设备时，网站仍可正常创建和参与挑战，但无法代替用户恢复已丢失的私密链接。界面需对此作简短、面向普通用户的说明。
- 私密管理链接属于敏感能力凭证：不得进入分析事件、日志、错误上报或公开 DOM 文案；本地列表应隐藏长链接并提供明确的移除能力。

#### 已确认规则

- 首页顶部增加“我的挑战”，与“制作挑战”“难绷排行”并列，通过同一页面内的标签状态切换。
- 最多保存最近 50 条本机创建记录，超过上限时移除最旧记录。
- 不仅依据挑战创建有效期自动删除，避免把仍在结果保留期内的单人挑战入口提前清掉。
- 不进行后台轮询；用户主动打开记录时才进入现有结果或管理视图获取最新状态。
- 支持删除单条记录与清空全部本机记录。

### 2. 昵称记忆

- 保存一个可编辑的“我的昵称”默认值，并在创建者昵称、群组参与者昵称等本人昵称输入框中自动填入。
- 不自动记忆好友昵称、邀请留言等不属于当前用户的信息。
- 读取和写入都必须执行与表单相同的去空格、长度限制和校验；存储失败时静默降级为现有一次性输入行为。
- 用户仍可在每次操作前修改昵称；后续输入覆盖本机默认值。

#### 已确认规则

- 创建挑战和参与群组挑战共用同一个“我的昵称”本机默认值。
- 只复用代表当前用户本人的昵称，不保存好友昵称或邀请留言。

### 3. 挑战意外退出恢复

- 恢复的目标是避免一次浏览器意外退出让挑战永久卡住，同时不创建第二条挑战记录、不重复计入排行榜或群组结果。
- 推荐方案：把当前挑战的尝试凭证及最少关联信息从会随标签页关闭而丢失的会话存储迁移到受限、带过期时间的本地活动记录中。
- 重新打开同一挑战时，若服务端仍为 `started` 且本机有匹配凭证，展示“上次挑战未完成”的恢复界面。
- 恢复后复用同一个服务端尝试资格，重新进行摄像头校准，并从视频开头重新开始；不恢复退出前的视频秒数、校准结果或过程分数。
- 完成挑战、凭证失效、挑战到期或服务端明确拒绝后，立即清除对应活动记录。
- 若本地凭证已被清理，客户端无法安全证明自己是原参与者；MVP 不应通过公开链接重置已开始的单人挑战。此时保留明确错误说明，并避免后台自动创建新尝试。
- 不依赖 `beforeunload`、`sendBeacon` 等关闭事件自动判失败，因为移动端进程回收、断网和系统崩溃无法可靠触发，容易误伤正常用户。

#### 已确认规则

- 意外退出后恢复原有挑战资格，不创建新尝试。
- 用户需要重新进行摄像头校准，并从视频开头重新挑战。
- 不恢复或持久化退出前的视频进度、校准状态、面部数据及过程分数。

## Requirements

- R1：成功创建单人、自我或群组挑战后，当前浏览器应自动登记一条可找回的本地挑战记录。
- R2：本地记录应支持版本迁移、损坏数据隔离、容量限制、过期清理和存储不可用时的无功能损失降级。
- R3：主页应提供不刷新页面的“我的挑战”视图，并遵循现有单页交互与视觉风格。
- R4：私密入口不得被分析统计、普通接口请求、日志或公开分享内容泄露。
- R5：本人昵称可跨会话复用，且始终允许现场修改。
- R6：可恢复的异常退出必须复用原尝试，不新增服务端挑战/参与记录，不在恢复前计入完成结果。
- R7：恢复流程不得持久化摄像头画面、人脸特征、校准数据或未完成的过程分数。
- R8：功能应覆盖浏览器刷新、标签页关闭后重开、浏览器进程异常退出和本地存储不可用等关键路径。
- R9：新增客户端存储键应统一命名、集中封装，并与现有 `sessionStorage` 兼容迁移，避免部署后让正在进行的挑战直接失效。

## Out of Scope

- 跨设备或跨浏览器同步“我的挑战”。
- 用户账号体系或服务端保存浏览历史。
- 精确恢复到退出前的视频时间点。
- 持久化摄像头、人脸特征、校准参数或未完成挑战曲线。
- 依靠页面关闭事件自动提交失败结果。

## Acceptance Criteria

- [ ] 创建单人、自我和群组挑战后，刷新首页仍能在“我的挑战”中找到对应入口。
- [ ] 用户能从本地记录进入私密结果，复制链接时有明确反馈，并能删除单条或全部本地记录。
- [ ] 本地记录损坏、超限、存储被禁用或处于隐私模式时，核心挑战流程仍可使用且不会白屏。
- [ ] 创建者和群组参与者的本人昵称会自动预填，修改后能在后续会话中使用。
- [ ] 挑战开始后关闭并重新打开浏览器，在凭证和服务端状态仍有效时能看到恢复入口。
- [ ] 恢复挑战使用原尝试资格，重新校准并从头播放，不产生重复完成记录或重复排行榜统计。
- [ ] 完成、到期或凭证无效后，本地活动凭证会被清理。
- [ ] 浏览器持久化数据中不存在摄像头画面、人脸特征、校准数据、临时视频地址或未完成的过程曲线。
- [ ] 新增交互在桌面端和移动端通过基础可用性验证，并通过现有 lint、类型检查和测试。
