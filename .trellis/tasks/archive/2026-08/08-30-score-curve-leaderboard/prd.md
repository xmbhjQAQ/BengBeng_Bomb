# 表情曲线与难绷排行榜

## Goal

让挑战者在结算时直观看见自己从平静到“绷不住”的量化变化，并在创建挑战的首页通过无刷新视图切换查看“难绷排行榜”，提升结果的可解释性和继续挑战的动机。

## Confirmed facts

- `/` 当前直接渲染 `ComposerView`，即用户截图中的“制作挑战”页面；客户端没有路由库，`App.tsx` 只按初始 `location.pathname` 选择页面。
- 推理过程已有 `SmileSample.smoothedScore` 和视频 `currentTime`，但当前只保留最新 sample 与最大值，没有保存时间序列。
- 当前隐私契约只向后端提交最终 outcome 和 elapsedSeconds；摄像头帧、landmarks、blendshapes、原始/平滑分数均留在浏览器。
- 结算组件同时用于挑战完成后的同页嵌入结算和公开 `/report/:token` 报告；公开报告目前只有 outcome、elapsed 与视频聚合统计。
- 后端 `video_stats` 只有 `video_key` 和聚合计数，没有排行榜展示所需的标题、封面等视频元数据，也没有现成排行榜 API。
- 首页新入口必须通过 React 状态切换“制作挑战 / 难绷排行”，不刷新页面、不跳转新 URL，并保持统一视觉与移动端可用。

## Requirements

- R1：在结算匿名热力图上方展示本次挑战的“绷住程度”折线图，横轴为视频时间，纵轴为归一化程度，并明确危险阈值/爆炸点语义；触屏端不依赖 hover。
- R2：曲线采样必须限频/降采样，不能保存摄像头帧、landmarks 或 blendshape 明细；无有效样本时提供明确空状态。
- R2a：每秒最多上传一个 0–100 的平滑量化分数点及对应视频秒数；曲线与完成 session 绑定，统一使用 Worker `RESULT_TTL_HOURS`（当前默认 48 小时）作为过期时间，管理入口销毁结果时同步删除，不能拥有独立硬编码保留期。
- R3：首页增加轻量、可访问的“制作挑战 / 难绷排行”切换控件，切换仅改变组件状态，不调用 location/history，不刷新页面。
- R4：排行榜作为独立首页视图，不与制作表单纵向堆叠；需有加载、空数据、错误与重试状态，并保持统一品牌视觉、过渡动画和 `prefers-reduced-motion` 支持。
- R5：排行榜数据由 Worker/D1 提供，必须设置最低样本门槛，避免 1 次挑战就占据榜首；不得展示挑战者或接收者昵称等个人信息。
- R5a：排行榜按视频难绷程度排序，不建立挑战者/昵称榜；首页只在用户切换到排行榜时懒加载，Worker 返回短时公共缓存响应，避免每次首页打开都查询 D1。
- R5b：上榜最低完成次数必须使用 Worker 配置项（建议 `LEADERBOARD_MIN_ATTEMPTS`，默认 5）并进行上下界校验，不能散落在 SQL 或组件常量中；缓存时长也使用独立服务端配置，当前建议默认 10 分钟。
- R5c：MVP 排行榜使用永久累计的匿名视频聚合，不新增按日统计表或时间窗口筛选；最近 7/30 天等时段榜留作后续独立扩展。
- R5d：每个排行榜条目提供两个不同动作：“我来挑战”在当前 SPA 中进入该视频的挑战流程；“分享给朋友”切回制作视图，复用该视频并继续填写发起人、接收者和留言。两个动作都不能刷新页面，且不能要求用户重新粘贴视频链接。
- R5e：“我来挑战”创建免昵称的单人模式；所有用户可见文案统一使用“单人挑战”，禁止使用“试炼”。单人模式的介绍页和公开报告不展示虚构昵称。
- R6：保留现有 48 小时挑战/结果配置、一次性挑战语义、Worker 中转和本地人脸检测边界。

## Acceptance Criteria

- [ ] AC1：一次有有效检测样本的挑战结束后，结算热力图上方出现可读折线，能识别时间、程度、阈值和终点；手机端可通过可见标签或触控读取关键点。
- [ ] AC2：无有效曲线样本时显示真实空状态，不伪造数据；长视频样本数受明确上限约束。
- [ ] AC2a：公开报告在结果有效期内可重新读取同一条量化曲线；修改 `RESULT_TTL_HOURS` 会同时改变结果和曲线保留时长，结果过期或主动销毁后曲线不可再读取。
- [ ] AC3：首页切换到排行榜及返回制作页时 URL、页面生命周期和已填写的制作表单状态保持不变。
- [ ] AC4：排行榜不会和制作表单同时作为主内容出现；桌面和窄屏均无明显挤压、溢出或不可操作控件。
- [ ] AC4a：排行榜条目的“我来挑战”可直接进入同一视频的挑战准备流程；“分享给朋友”保留视频选择并回到装填挑战步骤，两者均不刷新且不会重新要求粘贴链接。
- [ ] AC4b：单人模式不要求昵称，介绍页明确显示“单人挑战”；全站新增文案中不存在“试炼”，报告不展示虚构挑战身份。
- [ ] AC5：排行榜 API、仓储聚合、排序/门槛和 UI 状态均有自动化测试；现有挑战、结算和热力图测试保持通过。
- [ ] AC6：lint、type-check、全部测试、Worker 测试和生产构建通过，并完成桌面/390px 交互检查。

## Out of scope (initial)

- 用户账户、登录系统和基于身份的个人排行榜。
- 最近 7/30 天等滚动时间榜、日聚合表及榜单周期切换。
- 上传摄像头图像、landmarks 或可还原面部特征的原始检测数据。
- 永久保存单次挑战的量化表情曲线，或将曲线纳入永久视频聚合。
- 引入多页面路由框架或为首页两个视图新增独立 URL。
