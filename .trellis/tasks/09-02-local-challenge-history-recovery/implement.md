# 本地挑战记录、昵称记忆与意外退出恢复实施计划

## Ordered checklist

1. **建立安全的本地持久化基础层**
   - 新增带异常降级的 `localStorage` 适配器、版本化 envelope 和运行时校验辅助。
   - 为昵称、创建历史和活动尝试建立独立模块及测试；历史上限固定为 50，upsert 去重并按时间淘汰。
   - 保证所有读取面对损坏、旧版本和超限数据时安全回退，且不输出能力凭证。

2. **接入本人昵称记忆**
   - `ComposerView` 和群组 `ChallengeView` 从共享本人昵称初始化。
   - 在有效失焦以及创建/开始成功时保存新值；空值和非法值不覆盖。
   - 添加创建场景与群组参与场景的预填、修改和存储失败测试。

3. **登记全部本机创建的挑战**
   - 抽取并校验 `CreatedChallengeRecord`，在 classic/group 创建成功后 upsert。
   - 扩展排行榜 self 创建响应，保存管理入口、视频元数据和有效期后再导航。
   - 测试三种模式、重复写入、50 条上限，以及创建成功但本地存储失败时仍展示/导航。

4. **实现首页“我的挑战”标签**
   - 将首页 tab 键盘逻辑改为三项有序循环，增加 `MyChallengesView`。
   - 实现空状态、最近记录列表、按类型区分的查看/管理/复制操作、单条删除和清空确认。
   - 复用现有 SPA/结果页面和复制反馈，不增加状态轮询，不渲染完整私密 URL。
   - 补充响应式样式、ARIA tab 关系、键盘操作和移动端列表验证。

5. **迁移活动 attempt 到可恢复存储**
   - 定义 single/group 活动记录并用 token + kind 精确匹配当前路由。
   - `/start` 成功后先持久化 attempt；新群组将 `attemptToken`、`attemptId`、nickname 原子保存，旧群组缺失 nickname 时仍允许只迁移原 bearer/id。
   - 兼容读取并迁移既有 sessionStorage 键；清理逻辑同时覆盖新旧存储。
   - 本地存储失败时不阻断本轮挑战，但保持现有 sessionStorage 作为本标签页降级。

6. **增加意外退出恢复状态**
   - `/open` 完成后判断本机有效活动记录与服务端状态，展示“上次挑战未完成”恢复卡片。
   - “重新开始本轮”复用原凭证，进入现有介绍/校准流程并从头播放，不调用 `/start`。
   - 完成、到期及明确鉴权失败时清理；网络/503 等暂时错误保留以便重试。
   - 处理 storage 跨标签事件，避免另一标签完成后当前页继续显示过期的恢复提示。

7. **回归与隐私检查**
   - 验证持久化内容中没有摄像头、人脸特征、校准数据、视频位置、过程曲线、临时播放 URL。
   - 验证管理链接与 attempt bearer 不进入日志、分析、可见长文本和分享图片。
   - 回归 classic/self/group 创建、挑战、完成、刷新结算、管理结果、群组结果和排行榜。

8. **质量门与真机 smoke**
   - 运行 `npm run lint`、`npm run type-check`、`npm test`、`npm run test:worker`、`npm run build`。
   - 桌面浏览器执行关闭标签恢复、双标签完成、清空历史；移动端执行进程退出后重开并重新校准挑战。
   - 记录无法模拟的浏览器进程回收边界和实际验收结果。

## Risky files / rollback points

- `src/client/app/ChallengeView.tsx`：attempt 生命周期、完成提交和单页阶段投影集中在同一组件，必须小步修改并优先补测试。
- `src/client/app/HomeView.tsx`：现有键盘 tab 逻辑写死为两项，新增第三项时要同步 ARIA 与测试。
- 新的本地存储模块：包含管理与尝试能力凭证，禁止调试输出；版本校验和清理必须在业务接入前独立验证。
- `ComposerView.tsx`：本地登记失败不得把服务端已经创建成功误报为“创建失败”。
- 本任务原则上不改 Worker/D1；若实现中发现必须改变后端生命周期，应暂停并重新审阅设计，不能顺手扩 scope。

## Definition of done

- PRD、技术设计和实施清单获得用户批准后才运行 `task.py start`。
- `prd.md` 每条验收标准都有自动测试或明确的桌面/移动 smoke 记录。
- 三种创建模式都可在同一浏览器找回；昵称可复用；单人和群组异常退出均复用原 attempt 从头恢复。
- 没有新增轮询、D1 schema 或挑战完成统计路径，Cloudflare 请求负担保持原模型。
- 全量质量门通过，既有单页挑战、私密结果和分享功能无回归。
