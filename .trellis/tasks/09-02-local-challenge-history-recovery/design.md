# 本地挑战记录、昵称记忆与意外退出恢复技术设计

## 1. 设计目标与边界

本功能增加三个纯客户端能力：本机创建记录、本人昵称默认值、活动尝试凭证恢复。服务端 D1 仍是挑战状态和完成结果的唯一事实来源；浏览器记录只是便利入口与恢复凭证，不能覆盖服务端状态。

本次不新增数据库迁移、Worker 路由或后台轮询。已完成结果的过程曲线仍只按现有私密结果策略保存；活动恢复记录绝不保存摄像头画面、人脸特征、校准参数、视频进度或未完成曲线。

## 2. 本地存储分层

新增统一的安全 `localStorage` 适配层，沿用 `session.ts` 的 try/catch 降级方式，并在业务层对 JSON 做运行时校验。建议使用三个互相隔离且带版本号的键：

| 键 | 内容 | 上限/清理 |
|---|---|---|
| `bengbeng:profile:v1` | 一个经过规范化的本人昵称 | 新的有效昵称覆盖旧值 |
| `bengbeng:created-challenges:v1` | 最近创建挑战的版本化数组 | 最多 50 条，按创建时间移除最旧项 |
| `bengbeng:active-attempts:v1` | 按挑战标识索引的未完成尝试 | 完成、拒绝或挑战到期立即移除 |

读取规则统一为：解析失败、schema 不匹配或超出合理尺寸时丢弃对应值，而不是让渲染失败。写入配额不足或被浏览器拒绝时返回失败，调用方继续现有流程。不要在存储模块、埋点或错误对象中打印私密字段。

## 3. 创建挑战注册表

### 数据模型

每条 `CreatedChallengeRecord` 保存：

- `version` 或由顶层 envelope 统一携带版本；
- 稳定 `id`（由挑战类型和公开入口确定，用于 upsert 去重）；
- `kind: 'classic' | 'self' | 'group'`；
- 用于列表展示的视频稳定元数据：BVID/page、标题、封面；
- `createdAt`、服务端返回的 `expiresAt`，以及群组可用的 `resultExpiresAt`；
- 对应的公开挑战/统一入口、私密 `manageUrl`，群组的公开 `resultUrl`；
- 可选发起者昵称，仅用于本机列表展示。

不保存临时 CDN 地址、解析 ticket、邀请分享图片、摄像头或挑战结果细节。

### 写入点

- `ComposerView` 在 API 返回且响应完成规范化后立即 upsert，再进入创建成功 UI。
- `HomeView` 的排行榜“我来挑战”创建 `self` 挑战时扩展响应类型，先登记完整记录，再 SPA 导航到挑战页。
- 同一公开入口重复写入时更新现有记录并移动到最新位置，不占用两个名额。

### “我的挑战”视图

`HomeView` 的标签集合扩展为 `compose | history | leaderboard`，键盘左右方向导航改为有序数组循环，不能继续使用二选一逻辑。

新增 `MyChallengesView`：

- 按 `createdAt` 从新到旧展示模式、视频、创建时间和本地可判断的有效期信息；
- 单人/自我挑战提供“查看状态与结果”（私密管理入口）和复制操作；
- 群组提供“查看群组结果”和“管理挑战”，公开入口与私密入口明确分开；
- 长链接只用简短标签呈现，不把完整凭证写进可见文本；
- 提供删除单条和二次确认后的“清空本机记录”；
- 空状态说明记录只保存在当前浏览器，清除浏览器数据或换设备后无法找回；
- 不主动请求状态。点击入口后复用现有 `ManageView`、`GroupResultsView` 或挑战页面完成服务端查询。

模块提供同页订阅通知（或等效 React 状态回调）并监听 `storage` 事件，使刚创建的数据及其他标签页的删除能刷新列表；通知内容不携带私密 URL。

## 4. 本人昵称记忆

新增 `readPreferredNickname` / `rememberPreferredNickname` 等集中接口：

- 读取时 trim，并按 `CLIENT_CONFIG.limits.nickname` 截断/拒绝异常值；
- `ComposerView` 的 `initiator` 和群组 `ChallengeView` 的 `nickname` 使用该值作为初始状态；
- 在昵称失焦且值有效时保存，并在成功创建/成功开始时再次保存，避免只靠某一个浏览器事件；
- 空值不覆盖已有默认值；用户输入的新有效值覆盖旧值；
- 不用于 recipient/message 等其他字段。

## 5. 活动尝试与恢复流程

### 数据模型

`ActiveAttemptRecord` 仅保存完成 API 所必需且可验证的字段：

- `kind: 'single' | 'group'`；
- 与当前 URL 精确匹配的挑战 token 标识；
- `attemptToken`；
- 群组的 `attemptId`；
- `startedAt` 和从已打开挑战负载取得的 `expiresAt`；
- 新版本群组本轮已提交给服务端的 nickname，用于恢复时保持身份一致。旧版本 session 迁移时 nickname 可能缺失，但不影响 `/complete` 鉴权，不能为了补齐它而伪造或再次创建参与记录。

不保存 `accepted`、校准进度、视频时间、评分采样或人脸数据。

### 启动写入顺序

1. 若已有匹配且未过期的活动记录，复用它，不调用 `/start`。
2. 否则调用现有单人或群组 `/start`。
3. API 成功后先同步写入活动记录，再更新 React 状态并开始视频。
4. 写入失败不阻断本轮挑战，但界面可在非干扰位置说明浏览器无法提供关闭后的恢复能力。

服务端返回和本地落盘之间仍存在极短的不可消除窗口；无账号且服务端只存 bearer 哈希时，客户端崩溃在该窗口内无法恢复。技术设计不通过降低鉴权强度来掩盖这一点。

### 兼容迁移

首次加载挑战时同时读取新活动记录和旧 `sessionStorage` 键：

- 新记录有效时优先使用；
- 仅有旧 session bearer 时继续本轮，并在取得服务端 expiry 后迁移到新记录；
- 群组必须把旧 `attemptToken` 与 `attemptId` 作为一个整体迁移；缺少 `attemptId` 时不伪造记录；缺少旧 nickname 时仍可迁移 bearer/id，并在恢复界面隐藏昵称输入而不要求再次 `/start`；
- 完成和失效清理同时删除新旧键，避免旧版本残留再次生效。

### 恢复交互

当 `/open` 显示单人挑战为 `started`，或群组本机存在有效活动记录，且本次页面是从持久记录恢复时：

- 先显示“上次挑战未完成”的恢复卡片；
- 主操作“重新开始本轮”只确认使用原 attempt，不调用 `/start`；
- 随后回到现有介绍/隐私 → 摄像头与校准 → 准备挑战 → 正式挑战流程；
- 用户重新校准并从视频开头开始，保持现有同页状态机；
- 可提供“暂不继续”返回首页，但不得删除尝试或把它计为失败。

完成提交成功后清理活动记录。若 API 返回明确的 attempt 无效、挑战过期、群组结束/销毁等不可恢复错误，也清理记录并展示对应普通用户文案；暂时网络错误保留记录以便重试。

### 并发标签页

本地恢复不是硬锁。多个标签页可能读取同一个 bearer，但服务端现有状态转换和幂等完成仍是最终保护：只有一个完成结果可计入统计。通过 `storage` 事件在另一标签完成并清理记录后提示当前页重新载入状态；不增加服务端锁或心跳。

## 6. 安全与隐私

- `manageUrl` 和 `attemptToken` 按能力凭证处理，禁止进入 Clarity 自定义事件、console、错误文案、分享卡片或公开链接参数。
- 使用现有 CSP 限制脚本来源；本任务不引入第三方持久化依赖。
- 页面只显示简短动作标签；复制操作读取内存中的真实 URL，并沿用已有复制成功/失败反馈。
- 清空记录时同时清空创建历史；活动中的尝试需单独明确处理，不能因清空历史误删正在挑战所需的 bearer。
- 浏览器本地存储不是云备份，必须在空状态或说明文案中清楚告知用户。

## 7. 后端与性能影响

- 无 D1 migration、无新 Worker endpoint、无定时任务。
- 历史和昵称操作为零网络请求。
- 恢复路径复用现有 attempt，因此不会增加 `/start` 写入；每次真正重新打开仍有现有 `/open` 和媒体准备请求。
- 历史列表不请求状态、不自动轮询。进入现有结果/管理页面时才按当前行为请求一次。
- `localStorage` 内容严格限于小型 JSON，50 条历史远低于通常浏览器配额。

## 8. 验证重点

- localStorage 禁用、抛错、配额满、JSON 损坏、旧版本、超 50 条和重复 upsert；
- classic/self/group 三类创建均被登记，私密入口不进入可见长文本；
- 首页三个 tab 的点击、键盘顺序、空状态、删除和清空；
- 昵称预填、修改覆盖、空值不覆盖及最大长度；
- 单人和群组在刷新、关页重开后的恢复，同一个 attempt 完成且只统计一次；
- 旧 sessionStorage 活动挑战可迁移；
- 完成/过期/无效凭证清理，网络错误不误删；
- 不持久化人脸、校准、视频位置和过程曲线；
- 现有挑战单页阶段、结算刷新、分享和排行榜行为不回归。
